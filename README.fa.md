وبو یک افزونه‌ی کروم برای کسانی است که زیاد می‌خوانند و بیشترِ آنچه خوانده‌اند را
فراموش می‌کنند. یک جمله را در هر صفحه‌ای انتخاب می‌کنید، یکی از پنج رنگ را به آن
می‌دهید و اگر لازم بود یک یادداشت کنارش می‌گذارید. هفته‌ها بعد، همان جمله در
داشبورد هست و با یک کلیک به پاراگراف اصلی برمی‌گردید.

رابط کاربری فارسی و راست‌به‌چپ است، چون برای همین نوع خواندن ساخته شده؛ اما روی
صفحات انگلیسی و چپ‌چین هم دقیقاً همین‌طور کار می‌کند.

هیچ سرور، حساب کاربری یا آمارگیری‌ای در کار نیست. هایلایت‌ها در حافظه‌ی محلی
مرورگر روی دستگاه خودتان ذخیره می‌شوند و هیچ‌چیز از صفحاتی که می‌خوانید جایی
فرستاده نمی‌شود.

## چه کار می‌کند

| امکان | توضیح |
| --- | --- |
| **پنج رنگ هایلایت** | زرد، سبز، فیروزه‌ای، صورتی و بنفش؛ از نوار شناور، منوی راست‌کلیک یا کلید `Alt+Shift+H`. |
| **یادداشت روی هر هایلایت** | روی هایلایت کلیک کنید تا کارتش باز شود. هایلایتِ یادداشت‌دار در متن و در داشبورد زیرخط می‌گیرد. |
| **برچسب مقاله** | تا هشت برچسب برای هر مقاله، برای مرتب نگه‌داشتن فهرست خواندنی‌ها. |
| **داشبورد** | جست‌وجو، فیلتر رنگ و برچسب، فقط یادداشت‌دارها، مرتب‌سازی، جمع‌کردن گروه‌ها و برگشت به پاراگراف اصلی. |
| **پشتیبان** | خروجی کامل JSON یا خروجی انتخابی (فقط بعضی سایت‌ها، مقاله‌ها یا برچسب‌ها). موقع بازیابی می‌پرسد ادغام شود یا جایگزین. |
| **خروجی خواندنی** | کتابخانه‌ی Markdown برای ابسیدین و هر ویرایشگر دیگری، و کتابچه‌ی آماده‌ی چاپ با فهرست مطالب. |
| **تم** | خودکار، روشن و تاریک. ویجت‌های داخل صفحه هم بی‌درنگ با تم عوض می‌شوند. |
| **خاموش‌کردن برای یک سایت** | وبو را روی یک دامنه خاموش کنید، بدون اینکه هایلایت‌های آن سایت پاک شوند. |
| **شمارنده روی آیکون** | تعداد هایلایت‌های صفحه، اگر بخواهید. |

## نصب

وبو در فروشگاه وب کروم نیست. از همان آرشیو انتشار داخل همین مخزن نصبش می‌کنید.

پیش‌نیاز: کروم نسخه‌ی ۱۰۲ یا جدیدتر، یا هر مرورگر کرومیومی که افزونه‌ی باز‌شده
(unpacked) را قبول کند.

1. فایل `dist/weboo-v0.12.0.zip` (یا جدیدترین `weboo-v*.zip`) را دانلود کنید.
2. آن را در یک پوشه‌ی دائمی باز کنید، مثلاً `Documents/weboo`.
3. به `chrome://extensions` بروید.
4. گوشه‌ی بالا **حالت توسعه‌دهنده** را روشن کنید.
5. **Load unpacked** را بزنید و پوشه‌ی باز‌شده را انتخاب کنید.

افزونه در نوار ابزار ظاهر می‌شود. هر مقاله‌ای را باز کنید و یک جمله را انتخاب
کنید تا نوار رنگ‌ها کنارش بیاید.

> پوشه‌ی `extension/` در این مخزن کد منبع است، نه بیلد قابل نصب. کروم آن را با
> خطای `Could not load options page 'dashboard.html'` رد می‌کند. این طبیعی است:
> یا از زیپ انتشار استفاده کنید، یا خودتان با `bun run build:wxt` بیلد بگیرید و
> `.output/chrome-mv3` را بار کنید.

## استفاده

**هایلایت.** متن را با ماوس انتخاب کنید. نوار ابزار بالای متن با پنج رنگ، دکمه‌ی
یادداشت و دکمه‌ی کپی باز می‌شود. یک رنگ انتخاب کنید تا هایلایت همان لحظه ذخیره
شود. راست‌کلیک روی متن انتخاب‌شده همین کار را می‌کند و `Alt+Shift+H` رنگ پیش‌فرض
را بدون باز‌کردن نوار اعمال می‌کند.

**یادداشت.** روی یک هایلایت کلیک کنید. کارت آن با متن نقل‌شده، تاریخ و جای
نوشتن یادداشت باز می‌شود. یادداشت را بعداً می‌توانید ویرایش یا پاک کنید. دکمه‌های
کپی و حذف هم روی همین کارت هستند.

**پاپ‌آپ.** آیکون افزونه فهرست هایلایت‌های صفحه‌ی جاری و تعداد یادداشت‌ها را نشان
می‌دهد. سوئیچ بالای صفحه وبو را فقط برای همان دامنه خاموش می‌کند. آیکون چرخ‌دنده
داشبورد را باز می‌کند.

**داشبورد.** هر هایلایت زیر مقاله‌ی خودش، با نام و فاویکون سایت، گروه‌بندی شده
است. می‌توانید در متن هایلایت‌ها و یادداشت‌ها جست‌وجو کنید، بر اساس رنگ یا برچسب
فیلتر بزنید، فقط یادداشت‌دارها را ببینید، گروه‌ها را جمع کنید و پاراگراف اصلی را
در تب جدید باز کنید.

**پشتیبان.** در داشبورد، «خروجی پشتیبان» همه‌چیز را در یک فایل JSON می‌ریزد.
«خروجی انتخابی» اجازه می‌دهد فقط بعضی سایت‌ها، مقاله‌ها یا برچسب‌ها داخل فایل
باشند. موقع بازیابی خودتان انتخاب می‌کنید که با داده‌ی فعلی ادغام شود یا کامل
جایگزینش کند.

**خروجی‌ها.** «خروجی Markdown» کل کتابخانه را در یک فایل Markdown با سربرگ YAML
می‌نویسد؛ هر مقاله یک بخش، آماده برای انداختن در ابسیدین. «کتابچه» از مقاله‌هایی
که انتخاب می‌کنید یک دفترچه با فهرست مطالب می‌سازد، برای چاپ یا ذخیره به‌صورت
PDF.

**تنظیمات.** تم (خودکار، روشن، تاریک)، رنگ پیش‌فرض هایلایت، نمایش یا عدم نمایش
نوار شناور، نمایش یا عدم نمایش شمارنده و فهرست سایت‌هایی که افزونه روی آن‌ها
خاموش است.

## حریم خصوصی

وبو هایلایت‌ها را در `chrome.storage.local` نگه می‌دارد. کلیدها به تفکیک سایت
ذخیره می‌شوند، تا خواندن هایلایت‌های یک سایت بقیه را اسکن نکند:

```
hlx:settings          تنظیمات کاربر (تم، رنگ پیش‌فرض، سایت‌های غیرفعال)
hlx:d:<host>          هایلایت‌های یک دامنه
hlx:f:<host>          فاویکون گرفته‌شده از خود صفحه، به‌صورت data URL
hlx:tags              برچسب مقاله‌ها، بر اساس URL نرمال‌شده
hlx:schemaVersion     نسخه‌ی شکل داده، برای مهاجرت‌ها
```

هیچ‌چیز آپلود نمی‌شود. تنها درخواست بیرونی‌ای که افزونه می‌تواند بفرستد، گرفتن
فاویکون خودِ صفحه از همان دامنه است و نتیجه به‌صورت تصویر محلی ذخیره می‌شود.
هیچ آدرس مقصدی در کد وجود ندارد.

چون همه‌چیز محلی است، حذف افزونه هایلایت‌ها را پاک می‌کند. اگر فهرست خواندنی‌ها
برای‌تان مهم است، اول پشتیبان بگیرید.

## زیر کاپوت

افزونه Manifest V3 است و با TypeScript، WXT و React نوشته شده.

- یک کانتنت‌اسکریپت روی صفحات `http` و `https` اجرا می‌شود. ماژول‌هایش به همان
  ترتیبی که مانیفست می‌گوید باندل می‌شوند و یک بررسی زمان بیلد جلوی به‌هم‌ریختن
  این ترتیب را می‌گیرد.
- هر هایلایت با یک لنگر ساختاری (دو XPath و آفست داخلشان) و متن اطرافش ذخیره
  می‌شود. بعد از رفرش، لنگر دوباره حل می‌شود؛ اگر DOM عوض شده باشد، متن قبل و بعد
  برای پیدا‌کردن دوباره‌ی جمله استفاده می‌شود و لنگر بی‌صدا ترمیم می‌شود.
- داشبورد یک صفحه‌ی React روی یک استور کوچک خارجی است، با نوشتن خوش‌بینانه و
  بازگشت در صورت خطا. قاعده‌ی انتخاب در پشتیبان و در کتابچه توابع خالص‌اند و بین
  پیش‌نمایش و فایل خروجی مشترک‌اند.
- ذخیره‌سازی نسخه دارد و مهاجرت‌ها فقط رو به جلو هستند. فیلدهای ناشناخته در
  رکوردها و در پشتیبان‌های وارد‌شده حفظ می‌شوند تا داده‌ی نسخه‌ی جدید با نسخه‌ی
  قدیمی‌تر صاف نشود.

پوشه‌ی `docs/` بیشتر توضیح می‌دهد: [معماری](docs/architecture.md)،
[ذخیره‌سازی](docs/storage.md)، [موتور لنگر](docs/anchor-engine.md) و
[بنچمارک‌ها](docs/benchmarks.md).

## توسعه

پیش‌نیاز: [Bun](https://bun.sh) نسخه‌ی 1.4.2 (در `package.json` پین شده)، Node.js
برای اسکریپت‌های بسته‌بندی و یک بیلد کرومیوم برای تست‌های مرورگر واقعی.

```bash
bun install
bun run build:wxt     # بیلد WXT در .output/chrome-mv3 و بعد بررسی parity
bun run zip           # خروجی تایپ، بیلد WXT، parity و ساخت dist/weboo-v<version>.zip
bun run test          # تست‌های واحد (bun:test + happy-dom)
bun run lint          # eslint
bun run typecheck     # tsc --noEmit
bun run harness       # ساخت دوباره‌ی هارنس E2E پاپ‌آپ
```

تست‌های مرورگر واقعی، کروم را از طریق پروتکل DevTools کنترل می‌کنند. مسیر
کرومیوم را در `HLX_CHROME` بدهید:

```bash
HLX_CHROME=<chromium> bun tests/e2e/real-theme-e2e.mjs    # چرخه‌ی تم در پاپ‌آپ و عوض‌شدن زنده‌ی تم روی صفحه
HLX_CHROME=<chromium> bun tests/e2e/next-compat-e2e.mjs   # ناوبری SPA و ریمونت
HLX_CHROME=<chromium> bun tests/e2e/real-backup-e2e.mjs   # پشتیبان انتخابی و جریان بازیابی
HLX_CHROME=<chromium> bun tests/e2e/real-booklet-e2e.mjs  # انتخابگر کتابچه، فهرست و فونت‌ها
HLX_CHROME=<chromium> bun tests/e2e/real-favicon-e2e.mjs  # گرفتن فاویکون
```

مجموعه‌ی واحد لایه‌ی ذخیره‌سازی، موتور لنگرگذاری، خروجی‌ها، خط داده‌ی پاپ‌آپ و
داشبورد، کف کنتراست تم‌ها و شکل بسته را پوشش می‌دهد.

## ساختار مخزن

```
entrypoints/          نقاط ورود WXT (بک‌گراند، باندل کانتنت، داشبورد)
extension/            کد اصلی محصول، همان‌طور که هست در بیلد کپی می‌شود
  content/            کانتنت‌اسکریپت، استایل هایلایت، گرفتن فاویکون
  shared/             لنگرگذاری، ذخیره‌سازی، خروجی‌ها، ویجت‌های رابط
  popup/              صفحه‌ی پاپ‌آپ (MVC)
  dashboard/          خط داده و استایل داشبورد
src/                  سورس TypeScript (به extension/shared کامپایل می‌شود)
  dashboard/          داشبورد React
  types/              مدل‌های دامنه، پین‌شده به رانتایم با تست‌های قرارداد
scripts/              بیلد، بسته‌بندی، ساخت آیکون، بررسی parity
tests/                تست واحد و تست‌های CDP با کروم واقعی
docs/                 معماری، ذخیره‌سازی، لنگرگذاری، بنچمارک
```

## نسخه‌گذاری و انتشار

هر تغییر با یک پله نسخه منتشر می‌شود: رفع اشکال، پچ؛ قابلیت جدید، مینور؛ تغییر
ناسازگار، ماژور. نسخه در پنج جای هماهنگ زندگی می‌کند که چهار تای آن با تست بسته
شده است.

زیپ‌های انتشار برای همیشه در `dist/` می‌مانند. آن‌ها تاریخ انتشار پروژه‌اند،
شامل آرشیوهای قدیمی‌تر `highlighter-extension-*` از پیش از تغییر نام در نسخه‌ی
0.8.0.
